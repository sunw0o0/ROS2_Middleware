# 싱글스레드 vs 멀티스레드 실행기

## 질문
콜백 처리 시간이 타이머 주기에 가깝거나 더 길어지면, ROS 2의 싱글스레드 실행기와 멀티스레드 실행기는 어떻게 다르게 동작하는가?

## 배경
ROS 2 노드의 콜백(타이머, 구독 등)은 실행기(executor)가 실행한다. `SingleThreadedExecutor`는 일꾼(스레드)이 하나라 콜백을 한 번에 하나씩 차례로 실행하고, `MultiThreadedExecutor`는 일꾼이 여러 명이라 콜백을 동시에 실행할 수 있다.
단, 한 노드의 콜백은 기본적으로 `MutuallyExclusiveCallbackGroup`에 묶여 한 번에 하나씩만 실행되므로, 동시에 실행하려면 `ReentrantCallbackGroup`을 함께 지정해야 한다.

예를 들어 비전 노드가 영상 하나로 라인 인식, 상자 인식, grasp 위치 계산을 모두 한다면, 처리 시간이 길어졌을 때 결과가 늦어지거나 빠질 수 있다. 이 실험은 그 상황을 단순하게 재현한 것이다.

## 방법
- 환경: PC 1대
- 코드: [thread_demo.py](./thread_demo.py)
- 노드 하나에 주기 1.0초인 타이머 두 개(A, B)를 만들고, 각 콜백 안에서 `time.sleep()`으로 일하는 시간을 흉내 냈다.


## 결과

### 실험 1: 일 0.5초 (A + B = 1.0초, 주기와 같음)

싱글에서는 B가 A가 끝날 때까지 기다려 매번 0.5초 늦게 시작했다. 멀티에서는 A와 B가 같은 시각에 시작해 함께 끝났고, 다음 타이머까지 0.5초의 여유가 남았다.
싱글은 A와 B의 합(1.0초)이 주기(1.0초)와 같아, 쉬는 시간 없이 100% 일하는 상태였다. 지금은 겨우 주기를 맞추고 있지만, 일이 조금만 길어지면 밀릴 것으로 보였다.

### 실험 2: 일 0.7초 (A + B = 1.4초, 주기보다 김)

<img width="936" height="1424" alt="Screenshot from 2026-11-09 03-02-10" src="https://github.com/user-attachments/assets/311d5956-8482-410a-ba4a-45ef61cd740e" />

| | single | multi |
|---|---|---|
| A 시작 간격 | 1.09 → 2.49 → 3.89 → 4.59 (약 1.4초씩 밀림) | 1.06 → 2.06 → 3.06 → 4.06 (정확히 1초) |
| 실행 횟수 | A 4번, B 3번 | A 4번, B 4번 |

**① 싱글은 주기를 지키지 못했다.**
A와 B를 합쳐 1.4초가 걸리는데 주기는 1.0초라, 한 사이클이 1초가 아니라 1.4초로 늘어났다. 1초마다 하라고 했지만 실제로는 1.4초마다 실행되었다.

**② 싱글에서는 B가 한 번 빠졌다.**
4.59초에 B가 실행될 차례였지만 A가 다시 실행되었다. 일이 밀려 A와 B가 모두 이미 실행됐어야 하는 상태가 되자, 먼저 만든 타이머인 A가 먼저 선택되어 B는 그 사이 기회를 놓친 것으로 보인다. 결국 B는 A보다 한 번 덜 실행되었다.

**③ 멀티는 주기를 그대로 지켰다.**
A와 B가 동시에 실행되어 각자 0.7초만 쓰므로, 1초 주기 안에 끝나고 0.3초 여유가 남았다. 시작 간격이 정확히 1초였고, A와 B 모두 4번씩 실행되었다.

## 결론
싱글스레드 실행기에서는 콜백이 차례로 실행되기 때문에, 처리 시간의 합이 주기에 가까우면 뒤에 실행되는 콜백이 항상 늦어지고, 주기보다 길어지면 주기 자체가 밀린다. 또 밀린 상태에서는 먼저 만든 콜백이 우선 실행되어, 어떤 콜백은 실행이 아예 빠지기도 했다.
멀티스레드 실행기와 `ReentrantCallbackGroup`을 함께 쓰면 콜백이 동시에 실행되어, 각 콜백의 처리 시간이 주기보다 짧은 한 주기를 그대로 지킬 수 있었다.

로봇에 적용하면, 카메라가 33 ms마다 영상을 보내는데 비전 노드가 여러 처리를 차례로 하느라 한 장에 40 ms가 걸리면, 결과가 점점 늦어지고 일부 결과(예: grasp 위치)가 빠질 수 있다. 따라서 무거운 콜백이 여러 개인 노드는 처리 시간과 주기를 함께 확인하고, 필요하면 멀티스레드 실행기를 쓰거나 노드를 나눠야 한다.

### 예상과 달랐던 점
싱글에서 주기가 밀릴 것은 예상했지만, B가 아예 한 번 빠질 것은 예상하지 못했다
